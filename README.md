# 한정 가위바위보 (Limited RPS)

카이지식 **한정 가위바위보**를 1대1 실시간 웹게임으로 구현한 MVP입니다.

각 플레이어는 바위/가위/보 카드를 정해진 장수만큼만 가지고 시작하며, 12라운드 안에 상대의 별을 모두 빼앗는 것이 목표입니다. Socket.IO 기반 실시간 대전, 재접속 지원, JSON 파일 영속 저장을 포함합니다.

- 스택: Next.js 15 (App Router) + React 19 + TypeScript + Socket.IO + Tailwind CSS 4
- 서버: Next.js 커스텀 서버(`server.ts`) 단일 Node 프로세스
- 공유 계약: `docs/SPEC-INTERFACE.md` (타입·이벤트·스토어 인터페이스의 절대 기준)

## 실행 방법

```bash
npm install
npm run dev
```

http://localhost:3000 에 접속합니다. 두 명이 플레이하려면 다음 중 하나의 방법으로 같은 방에 입장하세요.

- 두 개의 브라우저(일반 창 + 시크릿 창)에서 각각 접속, 또는
- 두 대의 기기에서 각각 접속

한쪽에서 "방 만들기"로 6자리 방 코드를 발급받고, 다른 쪽에서 "방 참가하기"에 코드를 입력하면 로비에서 만납니다. 양쪽이 준비(ready)를 누르면 게임이 시작됩니다.

## 프로덕션 실행

```bash
npm run build
npm start
```

`npm start`는 `NODE_ENV=production tsx server.ts`를 실행합니다. 포트는 환경변수 `PORT`(기본 3000)를 사용합니다.

## 테스트

```bash
npm test        # vitest run (unit + integration)
npm run typecheck  # tsc --noEmit
```

- **엔진 단위 테스트 21개** (`tests/unit/engine.test.ts`): 초기 상태, 가위바위보 판정, 제출 검증, 별 이동, 종료 조건(별 0 / 12라운드 완주 / 타임아웃), 마스킹 뷰(`toPublicView`)에서 상대 카드 정보 비노출 등.
- **소켓 통합 테스트 10개** (`tests/integration/socket.test.ts`): 실제 서버를 ephemeral 포트로 띄워 socket.io-client로 검증 — 전체 3연승 즉시 종료 플로우, 12라운드 완주(3-3 무승부), 비공개 보장(상대에게 카드 정보 전달 금지), 재접속 복구, 세 번째 입장 거부(FULL), 에러 코드 4종, 중복 제출, 미보유 카드 제출 거부, 몰수(forfeit), 로비 나가기.
- 총 **31개 테스트 전부 통과** (`npm test` 한 번으로 실행).

## 환경변수

`.env.example`을 복사해 `.env`로 사용하세요.

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | 서버 포트. Railway 등 PaaS는 자동 주입 |
| `DATA_DIR` | `<repo>/data` | 방 JSON 저장 디렉토리 (`data/rooms/<CODE>.json`) |
| `RECONNECT_GRACE_MS` | `60000` | 연결 끊김 후 재접속 유예 시간 (ms). 초과 시 몰수패 |
| `LOBBY_EXPIRE_MS` | `1800000` | 마지막 활동 후 게임 미시작 방의 만료 시간 (ms, 30분) |

저장은 원자적 쓰기(tmp 파일 작성 후 rename)이며, 재접속 토큰은 평문이 아닌 sha256 해시로만 보관됩니다.

## 게임 규칙 요약

### 초기 지급
- 바위 ✊ / 가위 ✌️ / 보 ✋ 카드를 **각 4장씩** (총 12장)
- 별 ⭐ **3개씩** (양쪽 합계 6개 유지)

### 라운드 진행 (5단계)
1. **Check** — 남은 카드를 확인합니다.
2. **Set** — 낼 카드를 고르고 SET 버튼을 눌러 제출합니다.
3. **Open** — 양쪽이 모두 제출하면 카드가 동시에 공개됩니다.
4. **Result** — 승패를 판정합니다.
5. **Update** — 별이 이동하고 다음 라운드로 넘어갑니다.

상대가 무엇을 냈는지는 공개 전까지 절대 알 수 없습니다. 한 번 제출한 카드는 소모되어 다시 낼 수 없으며, 남은 장수가 0인 카드는 선택할 수 없습니다.

### 별 이동
- 이긴 사람 별 +1, 진 사람 별 −1 (무승부면 이동 없음)

### 승리 조건 (우선순위 순)
1. 상대방의 별이 **0개**가 되면 즉시 승리 (`stars_zero`)
2. **12라운드**를 모두 소모하면 별이 많은 쪽이 승리 (동점이면 무승부, `cards_exhausted`)
3. 게임 시작 후 **4시간**이 지나면 별이 많은 쪽이 승리 (동점이면 무승부, `timeout`)
4. 상대가 재접속 유예 시간(60초)을 넘기면 몰수승 (`forfeit`)

### 재접속
연결이 끊겨도 60초 안에 다시 접속하면 토큰 검증 후 게임을 이어서 할 수 있습니다. 재접속 정보는 브라우저 localStorage(`lrps:<방코드>`)에 보관됩니다.

### 중요한 수학적 특성: 12라운드 완주는 항상 무승부

12라운드를 전부 완주하면 카드 분배 제약상 **별이 항상 3-3 동점이 되어 무승부가 강제**됩니다. 이유는 다음과 같습니다.

- 완주 시 각 플레이어는 바위/가위/보를 정확히 각 4장씩, 총 12장을 모두 사용합니다.
- 카드를 숫자로 두면(바위=0, 보=1, 가위=2), A가 이긴 라운드의 (A카드−B카드)는 mod 3에서 1, B가 이긴 라운드는 2, 무승부는 0이 됩니다.
- 12라운드 전체의 (A카드−B카드) 합은 (A가 낸 카드 총합) − (B가 낸 카드 총합) = 12 − 12 = 0이므로, **A승 횟수 − B승 횟수는 3의 배수**일 수밖에 없습니다.
- 그런데 승패 차이가 3에 도달하는 순간 패자의 별이 0이 되어 그 전에 게임이 조기 종료(`stars_zero`)됩니다.
- 따라서 완주했다는 것은 차이가 3의 배수이면서 3 미만이라는 뜻 → 차이는 0, 즉 별 3-3 동점, 무승부입니다.

**실전적 함의:** "12라운드 완주 → 별 비교"는 사실상 항상 무승부이므로, 실질적인 승부는 상대의 별을 0으로 만드는 것(연승)에 달려 있습니다. (명세서 §12 테스트 1의 "7승 5패" 예시는 도달 불가능한 시나리오이며, 단위 테스트는 "12라운드 전부 무승부 → 3-3 동점 무승부"로 작성되어 있습니다. 정정 기록: `docs/SPEC-ERRATA.md`)

## 프로젝트 구조

```
limited-rps/
├── server.ts                  # 진입점: startServer(PORT) 호출만
├── src/
│   ├── shared/types.ts        # 전 파트 공유 타입·상수 (Node API 사용 금지)
│   ├── game/engine.ts         # 게임 엔진: 순수 함수, 결정론적, I/O 없음
│   ├── server/
│   │   ├── start.ts           # HTTP + Socket.IO 서버 기동 (테스트용 랜덤 포트 지원)
│   │   ├── sockets.ts         # 소켓 이벤트 핸들러 (판정은 engine.ts 경유만)
│   │   └── store.ts           # JSON 파일 스토어 (RoomStore 인터페이스)
│   └── app/                   # Next.js App Router UI
│       ├── page.tsx           # 메인: 방 만들기 / 참가하기 / 게임 방법
│       ├── room/[code]/page.tsx  # 로비 + 게임 UI
│       ├── how-to-play/page.tsx  # 게임 방법 설명
│       ├── components/        # CardButton, Modal, Stars, Toaster
│       └── lib/socket.ts      # 클라이언트 소켓 래퍼
├── tests/
│   ├── unit/engine.test.ts    # 엔진 단위 테스트 21개
│   └── integration/           # 소켓 통합 테스트 10개
├── docs/
│   ├── SPEC-INTERFACE.md      # 공유 인터페이스 명세 (모든 파트의 절대 기준)
│   └── SPEC-ERRATA.md         # 명세서 정정 기록 (사용자 승인, 2026-10-15)
├── data/                      # 방 JSON 저장소 (git 제외)
├── .env.example               # 환경변수 예시
└── DEPLOY.md                  # 배포 가이드
```
